# 机会准备

用户在已经开始的主交流里明确开启范围许可后，新完成的 Learn 机会分区可以触发一次准备。默认关闭；旧机会须逐项选择。许可绑定当前真实工作目录、本交流及未来被引用的消息、明确选中的附加原件和最多四个普通文本文件。来源撤回优先；查看、已读、方法采用或目标状态都不是授权。

程序先读取有限原件并冻结实际作者、原文、来源版本、控制状态、许可和文件原字节摘要。每文件最多 256 KiB、合计 512 KiB，完整输入 JSON 最多 1 MiB；超限停止，不截断材料。文件内容读取和摘要在同步事务外完成，事务复核身份。模型选用当时原生网页默认 provider/model/reasoning，固定最多 8192 输出 token；已有路线不支持时诚实停止，不更换模型。之后修改默认只影响下一次准备。

每个机会最多创建一份实际执行记录。自动准备在输入检查失败后也不后台重试，用户可先查看原因再明确重新提交；宿主同时只有一个准备 Agent，主交流和 Learn 不等待它。唯一执行者是官方 Agent：create 一次、followup 一次、一个 turn 内最多 4 次模型请求、6 次获准执行的根工具动作和 5 分钟。原始消息 source 是 arcfold/preparation，属于程序，不是用户新原话。专用 preset 仅含原生 read/write 和原生工具执行器；原生文件观察策略必须实际提供 createIfAbsent。禁止命令、子代理、目标驱动、学习递归、权限提升和其它文件写入。

输出只能新建在 `.arcfold/preparations/<runId>/draft.md`，最多 64 KiB。必须在后续实际步骤全文回读，再有非截断正式答复、完整持久化与相同原生前缀，才一起登记稿件和未读通知。read 的三个容量上限仅在准备 preset 内均为 262144；检查行号、全部行、总行数以及模型可见内容。原字节 hash 另算：原生 write.after 是供差异展示的 LF 规范文本，不能冒充磁盘原字节。

停止先保存决定，再取消对应原生 handle。已经写出的文件和正式历史保留；来源或许可晚撤回时，交付事实仍保留，但不会显示为仍可使用。网页继续需要用户新写完整原话，经过原生 SessionController.prompt；只有同 session、rpcId、source=user 和全文相同的原件出现后才关联。重复或未知提交不重发。

重启只读既有原生会话和文件来核对，不 resume、不 followup、不重新创建 Agent。完整稿件可补登记；结果不明保留 unknown，费用未知继续由既有账本独立记录。关闭插件先停止受理，取消并等待当前原生执行结束，之后才关闭业务存储。没有新的模型商、凭据来源、费用上限或第二执行循环。

模型请求列表记录准入意图，不冒充实际出站；末次检查仍可在已登记后拦住请求。忽略一个候选只停止该候选的准备，不取消同一交流中其它已获准的准备。

源码和合成原生装配证明程序边界；安装网页流程由组合验收另行观察。文件完成与通过程序检查不证明机会价值或内容质量，也不代表用户采纳。

若模型一批提出的工具动作会超过六次，已有工具守卫整批拒绝。超额意图和被拒调用仍按原生事实完整保存，不为计数删日志。第五次模型请求不会实际出站。

继续入口在保存提交前检查当前原生注册的 Arcfold 主 Agent，并在发送前再次核对同一个对象与 preset。只有历史绑定、已关闭或被换掉的会话不能借此自动恢复；原生 prompt 语义保持 queue。许可重复请求不会重复取消，忽略决定只有实际提交成功后才取消对应准备。
