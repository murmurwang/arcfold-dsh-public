# Desktop 复用 DSH 模型配置

本文件说明候选 0.5.0 的实现。产品决定见 [决策](notes/native-model-configuration.md)。离线模拟只能证明调用途径和约束，不能证明任意模型的实际效果；尚未合入或发行，也没有更改日常 DSH。

## 用户会看到什么

用户在 DSH 的“设置 → 模型”配置服务商、连接地址和凭据，在聊天输入框选择模型和思考强度。Arcfold 不增加模型目录、密钥表单或另一个默认选项。一轮开始后，归属判断、主回答及其后台处理沿用该轮选择。进行中换模型会保存在 DSH 中，从下一轮开始使用。

首次启用会说明主回答之外还有后台调用，并由用户确认费用。0.4.x 的 DeepSeek 使用确认不被当作任意服务商的授权：更新后先显示“沿用 DSH 的模型设置”，确认后保留原数据继续使用。没有调用真实模型来完成设置。

## 一轮消息如何运行

1. DSH 原生选模器记录会话选择。`src/tree/native-models.mjs` 的 `bindNativeTurnSelection` 在一轮进行时保持原选择，新的选择仍写入 DSH 的原生会话事件。不同会话各有自己的状态。
2. `TreeRuntime.prepareAdmitted` 用 `captureNativeSelection` 向 DSH 查询该模型实际接受的参数和输入容量。这一步只准备连接，不发送模型消息。默认参数由服务商决定；不支持的模型或参数报错，不换用其他服务商。
3. `AttributionService` 根据本轮用户原话和目标信息发起归属判断。主回答与该判断都把实际服务商、模型、思考强度和输出上限存入各自的 `tree_jobs` 记录。后台模型来源由 `backgroundModelConfig` 沿来源任务、来源轮次或最新相关主对话查找；找不到来源就停止。
4. `TreeModelOwner` 仍通过 DSH 创建或恢复任务会话，把 `src/tree/prompts.mjs` 中相应角色的固定提示词和冻结的输入交给 DSH。角色分别为主回答、归属、学习、整理、检验、改进、脚本编写。后台保留各自输出上限；只读任务没有工具，脚本编写只获得原有受限工具。
5. 每次实际调用前，`assertProjection` 核对会话、模型参数、提示词、输入来源和工具权限。通过后登记一次调用，再由 DSH 已选服务商的原生连接发送。Arcfold 不组装另一套 HTTP 请求，也不读取凭据。
6. `NativeModelRecords` 保存服务商返回的用量和结束状态。完整回复经原有格式、来源和版本核对后，才允许写入 Arcfold 数据。后台结构化结果不合格、输出耗尽或版本过期时，保留原文及失败状态，不提交有效结果，也不自动重发。
7. 后续学习从主对话的持久记录取得选择。会话后来换模型或另一段聊天开始，都不改变已登记任务。重启时先核对已保存结果；已发起但结果不明确的调用保持未知。

通常一轮包含一次归属判断、一次主回答和相关节点的后台学习；有工具往返时主回答可能多次调用，其他后台任务由原有条件触发，调用次数并不固定为三次。

## 输入长度、用量与费用

新通道使用 DSH 自身的输入长度估算，并明确标为 estimated。学习内容接近所选模型容量时暂停追加，按原有流程整理；容量未知时不宣称输入一定安全，实际模型错误仍由 DSH 报告。旧实验模式的精确计数和预算约束没有放宽。

调用记录附在 `tree_invocations.nativeRequest`，包括实际模型参数、开始和结束时间、回复状态，以及服务商提供的用量。完整回复与费用结算是两件事：缺少用量不会凭空变成零 token；没有价格资料时费用为 null、价格状态为 unknown，不写成结算成功。这里的开始时间表示进入原生连接流程，不证明请求已到达远端。

用量来源明确记录为 DSH 原生连接。部分连接会把缺失计数初始化为零；无法区分真实零值和缺失值时，保留连接给出的原值供核查，但用量状态标为未确认，不作为已知零用量。Arcfold 不绕开原生连接读取另一份网络响应来推算费用。

## 安装、升级与隔离

`scripts/package-release.mjs` 在 Desktop 安装包中移除共享补丁对原生 DeepSeek、账户连接、其他服务商连接和默认模型的覆盖；命令行的旧预算模式仍使用原来的补丁。原生模型页和选模器来自 DSH 0.2.2-rc.1，未复制它们的实现。

`src/desktop/native-setup.mjs` 保存新通道的独立确认记录。升级前核对旧配置摘要、数据位置和旧费用记录的文件身份，保留旧文件；`activateNativeDesktop` 只更新 Arcfold 自己的运行条目并停用旧专用连接，不写原生服务商设置或默认模型。旧的尚未发送任务标为取消并保留输入；已经发送但未确认的任务不换通道重发。原始聊天、目标库和旧费用记录留在原位置。

新版实际运行不需要 DeepSeek 专用 Python 计数器。安装包暂时保留旧计数器和连接实现供旧配置检查及独立实验使用；它们不属于新 Desktop 调用路径。

## 检查入口与尚未验证项

- `test/native-model-integration.test.mjs`：实际 DSH 循环、原生 DeepSeek 与 pi-ai 连接、本机模拟服务；检查换模型、后台继承和并行聊天。
- `test/native-model-records.test.mjs`：七种角色的结果处理、缺失或无效用量、费用未知、错误、取消、部分输出、重启和禁止重发。
- `test/native-model-selection.test.mjs`：任意服务商思考档位、无思考参数、有效默认输出上限和一轮中途切换。
- `test/native-desktop-setup.test.mjs`：首次设置、旧配置确认、数据保留、失败后重启和默认模型不被覆盖。
- `test/desktop-setup.test.mjs` 与 `test/package-release-desktop.test.mjs`：新界面不注入专用模型表单，实际安装包保留 DSH 模型入口，旧模式仍受原约束。

原版 Desktop 的实际安装、更新和视觉验收，以及不同服务商真实模型的质量、速度和扣费，需在后续验收中单独确认。本 PR 不授权这些付费调用或日常环境更新。
