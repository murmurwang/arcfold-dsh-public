# Native model selection commit hook

The optional `session/select-model` event runs after the native controller validates a choice, before its original selection commit. Both native browser entries still call `session/selectModel`. No listener preserves the original behavior. The copied selection is frozen; the payload contains the actual Agent. The loaded `SessionController.modelSelectionSeam` capability identifies this exact patch, not an installed product handler.

`createModelSelectionHandler` acquires the native Agent maintenance phase, then validates, awaits native default saving, records the native session selection, confirms its writer and reads both choices back. Active work refuses the setting change. Input arriving during saving stays in the native inbox. There is no second session/model store or execution queue. The default and session writes are separate: failure preserves actual partial state and never claims rollback.

The two-file controller patch is pinned to official 0.2.2-rc.1 bytes. Its manifest and receipt preserve originals. All package patchers share the same exact-byte implementation; the two existing provider manifests and resulting package bytes are unchanged. The installer now patches the actual controller copy and records its independent proof. Proving the unique handler/service ownership at startup, exposing independent Learn settings, and real browser verification remain subsequent integration obligations. Bundling this component does not activate it.


## Installed controller proof

The official web bundle declares `session-controller` as `@deepseek-ai/dsh-api-session-controller`. CLI profile boot composes that row into the root Include at `profile/cordis.yml`; Include uses the profile directory as its module base. The installer therefore looks up the controller from that base with official `packageOf` and actual Node resolution, and requires the same entry file. It does not use either Arcfold provider wrapper or the web bundle source directory as the controller's importer. The official resolver can select the installation's host or profile copy; either is accepted only inside this selected installation. The two provider wrappers still require their copies inside the selected profile.

The installer checks all three exact original package states before changing any package. It then applies the accepted two provider patchers and the unchanged controller patcher in order, retaining separate exclusive receipts. Loading the actual controller must expose the frozen `SessionController.modelSelectionSeam === 'session-model-selection-commit-v1'` capability; a cached original module fails even when disk bytes were patched. This inspection imports the class but does not start a controller service, session or model request.

`installation.modelSelection` records `{path, patchId, receipt, receiptSHA256}`. Readback verifies the expected package/version, manifest, patched bytes, matching receipt and the complete installed file inventory; additions such as a shadowing nested copy are detected. It remains a read-only check with no installed-code imports. Older receipts without this field remain readable and do not acquire new model-selection authority. Frozen supply payload/consumer proofs precede patching; the final complete installation inventory follows patching.

Release dependency evidence now includes `dependencies.modelSelection` alongside both transport proofs and verifies the loaded controller capability from the dependency root. The helper and manifest were already packaged by the accepted seam task; no dependency or official serializer is changed. These local package/receipt tests do not prove the later unique product handler, browser save behavior or complete installed runtime.
