# 发行、装配与公开本地交付

发行把 Arcfold 业务与网页面板装进固定官方 DSH，不另造聊天、审批或任务执行器。本文是实现及交付要求；每份发行是否完成实际安装、浏览器和数据保留验收，以该发行清单为准。

## 同一份源码产生两包

`@arcfold/dsh` 是核心，`@arcfold/dsh-method-ui` 是唯一网页插件。核心声明有序 `dsh.bundle.patch`：先 `cordis.patch.yml`，再 `presets/arcfold.patch.yml`。宿主按 `@deepseek-ai/dsh-base → @deepseek-ai/dsh-web-app → @arcfold/dsh` 装配；UI 用包名加载一次，不能引用开发工作目录。主包不嵌入第二份网页包。

打包在私有 staging 中用锁定工具构建 `lib/client.js`，只外部引用宿主 React。清单绑定源文件、两份归档、UI 构建物与能力证明。依赖供给必须在两包生成之后产生，作为发行旁的独立材料：profile 锁含两包完整性，不能再打回同一核心归档形成自引用。

固定 DSH 0.2.2-rc.1、Cordis 4.1.0、Node 24.15.0、pnpm 11.28.5；当前安装支持 macOS arm64。费用证据要求 POSIX 权限，Windows 明确拒绝；Linux 未据此获得验收。

## 固定锁与实际消费包

准备供给先用官方解析产生 host/profile 锁，保留初次安装与命令原件，再将最终输入放入全新目录，使用与产品安装相同的 frozen install 流程离线重建。只有重建树的包内容、实际声明消费者和共享关系通过严格核对，才封存 supply。它不把 seed 缓存锁或首次 add 的物理布局当产品安装证明。

这继承了先前 zod 与 Smithy 的差异经验：同锁的 add/frozen hoist 路径可能不同，甚至实例多重集与共享改变。新方案从共同 frozen replay 生成基准，不靠删除消费者断言或粗略去重过关。原初次树与失败现场不覆盖。

安装定位核心实际消费的 DeepSeek、pi-ai 和原生 model-selection 包，核原版字节后使用既有精确补丁。磁盘回执与已加载模块能力分别核验，原版缓存模块不能仅凭磁盘正确被采用。最终 installation 清单保留实际路径、补丁回执和完整文件身份。构建检查不能替代这份新安装副本证明。

首次生成新的官方 profile 才用 `--from-default-profile web`；它会替换同名配置，因此不能对日常已有 profile 重做。日常 start 只使用已安装版本和个人数据。

## 主工作、学习和费用边界

外部配置由公开 init 生成，版本 profile 与持久 nativeHome 分开。本地初始化的默认回答模型为 `deepseek-official/deepseek-v4-pro/high`，Learn 只在初始化时复制这些值，此后独立。v2 routes 明确两路线的地址、网络、政策、费用范围与凭据引用，不从消息、工具参数或环境变量推断授权。设置三字段不改输出上限、政策或累计费用。

运行时使用一个共享费用宿主与两个自有薄封装，真正模型执行仍是官方适配器。OpenAI 的官方 pi-ai 是 wrapper 的真实子插件，启动核其父子关系、同一 LLM、原生请求处理器及实际配置；后续变动关掉发送门直到正常重启。每次真正发送前再次同步核归属、取消、业务输入和费用授权，无备用全局 fetch 或其它模型路线。

主 preset 保留官方文件读写、shell、skills、提问、todo、执行目标和公共 URL fetch，原生工作区、审批与 sandbox 权限保持。辅助学习 preset 无工具；一次冻结输入、一次辅助请求，未知不自动重发，独立分区提交且保留原输出。它不是另一条可随便发话的聊天入口。

唯一官方 goal-round-driver 在根层装配，不能在各主 preset 重复挂载。真实委托及原生当前 active/armed 状态决定自动续轮；程序来源不伪装用户原话。自动轮完成/受阻后只允许正式文字收尾，不能继续工具；主预设关键配置改变仍要求重启。jobs 完成采用 quiet，不给已暂停目标另造自动唤醒。

未接入的替代模型路由、模型自动重试/标题、子 Agent、调度、收费搜索和模型工作流继续关闭。三项 DeepSeek 请求扩展关闭但本地持久化与查询保留。长期目标/方法/机会不增加执行授权；其他后台准备能力未因本品牌任务而开放。

新 init 显式创建独立网页账本，不复用开发 ¥150。旧 limited/mixed 模式不变；OpenAI 仍 tokens-only。未知费用不清零，不把工程模拟的用量或费率当真实账单。

## 网页呈现与不可冒称部分

只关闭官方品牌贡献，复用三个官方位置显示 Arcfold。原生外壳、导航、输入框、语言选择和审批保留；状态固定值有中英文说明，所有原文保留。官方预构建的标签页标题和 hero 标题文字不随启动环境变量变化，当前不提供自建 frontend 或 DOM 改写。

已支持独立安装/初始化、主与学习模型独立设置、本机网页访问保护、原生委托续轮、旧资料预览确认/撤回与旧 3 只读导出。具体发行的机会准备、实际安装和网页呈现验收结果，以及仍未通过或尚未验证的事项，以随发行提供的交付清单（DELIVERY）为准；历史安装证据不自动证明最终组合包已交付。

一次真实纠正试验已核实两答核心判断、后台形成方法和跨源码对象领取完整指导，同时保留同聊原纠正、篇幅及局部措辞问题。它没有证明方法带来的独立因果收益或长期有效性，旧失败也未覆盖；单次耗时与范围见[README](../README.md#能力与证据边界)。

## 公开本地目录的最终交付

维护者应新建一个用户可找到的目录，例如用户指定的 `Arcfold/`。下列是必须完成并记录的交付动作，不是本次作者已执行的声明。

| 位置 | 交付内容 |
|---|---|
| `source/<commit>/` | 最终接受提交的独立源码与 Git 历史；不能用指回私有工作树的 worktree、共享 objects 或符号链接冒充 |
| `releases/<release>/` | 两份新归档、manifest、UI 构建回执与对应 runtime 供给/锁；不沿用旧包的 supply |
| `launcher/<release>/` | 同一核心归档解出的公开 `bin/arcfold.mjs`；不新增替代启动器 |
| `versions/<release>/` | 用公开 install 在永久目录真正新装；不可搬动临时安装树，因为回执绑定实际路径 |
| `local.json`、`personal-data/` | 用户配置、原生数据、凭据与账本；是私有运行数据，排除出发行与源码归档 |
| `archives/<release>/` | 旧发行与验收记录、兼容旧安装的路径，供公开 use-version 回退；不覆盖新数据 |
| `docs/architecture/<commit>/` | 对应最终提交的静态图数据与经筛选源码摘录，不提供任意磁盘读取 |
| `DELIVERY.json` | 上述真实路径、源提交、归档/清单 hash、回退目标、平台、实际验收与未完成边界 |

最终验收必须检查源码脱离私有 manager 后仍可追溯、归档不含密钥/个人库/请求原件/manager 文件、两包与供给一致、永久安装实际启动、桌面及 390px 品牌和原生功能、停止及兼容回退保留数据。阅读设置和资料本身应无模型请求。只在本机提供的架构 HTTP 页须标明提交；旧 gen7 预览是历史快照，不能标成当前完整产品，最终重建与端口另由交付记录确认。

公开目录交付不移动或替换原日常网页，也不自动迁移旧凭据或真实数据。需要迁入的资料仍走用户明确选择与预览确认。
