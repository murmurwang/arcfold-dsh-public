# OpenAI metered backend and runtime composition

The original backend slice is now connected to explicit arcfold-local-v2 runtime routes and the shared final dispatch guard. Activation requires explicit non-secret configuration and a new exact installation proof for the actual consuming pi-ai package. This runtime task changes no credential, installer or daily settings UI. Its local fixtures do not prove combined packaged-browser behavior. Independent daily main/Learn settings, fee display and the actual installed web flow remain delivery work.

## Actual request chain

1. A native DSH Agent starts a session turn/step. Existing Arcfold main or LearningRunner guards establish its business ownership. The shared host's early llm/stream listener checks native content/tool/schema/model bounds only; it does not run native ownership before the learning single-call guard. OpenAI admits durable user/tool image references; other routes keep their own content constraints.
2. The exact patched official dsh-llm-pi-ai plugin synchronously emits llm-pi-ai/request-transport. openai-provider requires the owned service, exact consuming-package hashes and loaded pi-ai-create-transport-v2 capability. It registers the explicit deployment subset of openai/gpt-6-astra and openai/gpt-6.1-sol; an unavailable mandatory transport rejects, never falls back to undefined. Invalid/Promise results are rejected by the accepted seam before credentials/attachments. Authorization service isolation prevents the official plugin from adding OAuth flows. A hook on that exact native fiber rejects changed volatile profiles before publication, so removing the explicit credential reference cannot enable ambient discovery.
3. MeteredTransport captures immutable messages, tools/history, model/output/effort policy and the original provider-independent native request identity. It returns one call-local sender. The official credential service resolves the explicit reference; the unchanged pi-ai translator and OpenAI SDK serialize history and create Responses SSE.
4. OpenAITransport validates the actual serialized POST. Only the fixed official /v1/responses endpoint (or an explicit loopback fixture), native text/image/client-function history, store:false, the frozen output count >=16 and pinned GPT-6 reasoning encoding are accepted. Native additional_tools developer declarations, encrypted reasoning, function IDs/results and configuration_update order are retained. Images are embedded bytes from DSH's durable attachment service, in user content or client function output, with the pinned translator's detail:auto. Server tools, remote image URLs, file IDs/uploads, unknown fields, account/project overrides, changed endpoints, service tiers and redirect overrides are rejected. Fixed short cache retention follows the official default; no long/explicit cache option can be injected.
5. One shared evidence root exclusively acquires a hash(requestId) directory, then persists attempt identity and the exact request body. OpenAI reserves its own token-only ledger; DeepSeek keeps its original monetary ledger/scopes and evidence version. Immediately before dispatch the shared host first checks the root runtime gate, then the same native identity, current main method/goal/source or frozen Learn input, cancellation and ledger authorization are rechecked synchronously. There is no await between these final checks and dispatcher.request.
6. An owned direct Agent or explicitly fixed HTTP CONNECT ProxyAgent sends once: idempotent:false, maxRedirections:0, no Retry/Redirect interceptor or proxy-to-direct fallback. The pinned SDK and native profile use maxRetries:0; a second use of the captured sender rejects. The evidence directory also prevents the same native step from gaining another send by selecting the other provider/ledger.
7. Shared lifecycle code saves original response bytes, ordered chunk offsets, status and hashes. ResponsesReceipt performs billing validation only. Valid completed or incomplete(max_output_tokens) terminal receipts with matching IDs/models and complete bounded usage settle before the terminal chunk reaches the official SDK. Missing/conflicting usage, failed/unsupported terminals, HTTP failures and interrupted dispatched requests remain unknown. Only demonstrably unsent attempts release.
8. The SDK/adapter remains the sole translator of answer, encrypted reasoning and tool history. Native tools/next steps/session persistence are unchanged. Cold recovery selects each registered protocol's original ledger/parser, verifies request/attempt identity and receipt bytes, and may settle a preserved complete receipt without sending. Unknown versions/conflicting ownership reject. Closing aborts/drains shared inflight work, closes owned dispatchers, then ledgers and the kernel evidence lock.

## Responsibility and accounting boundaries

The two registered OpenAI models advertise text and image input through the native model registry; the existing DSH browser uses that registry to decide whether a screenshot can be sent. There is no separate UI override. The shared transport accepts image blocks only through OpenAI's protocol-specific reference validator. DSH still verifies attachment hashes, types and dimensions, derives the request image version and performs the sole wire translation. An offloaded historical image remains a durable reference but is sent as a native text placeholder, without reloading its bytes. Images do not change request identity, ownership, cancellation, evidence or raw usage accounting. The existing total serialized request limit remains 16 MiB; this change does not promise unbounded image history.

- src/metered-transport.mjs owns send/failure/interrupt/finish/recover/close once. DeepSeekTransport is a protocol facade; its public sender, arcfold-messages-transport-v1 evidence and financial arithmetic remain compatible.
- src/native-request-authority.mjs extracts the existing identity and final business checks. The requestId algorithm remains dsh-messages-hash(sessionId,turn,step,stepStartSeq) across both providers. Learn must already be submitted with dispatchCount===1; metadata.role grants no new spending authority.
- src/metered-provider-host.mjs owns one evidence lock, immutable route registry, both ledgers and cancellation. Explicit routes use network:{mode:'direct'} or network:{mode:'proxy',url:'http://host:port/'}; URL credentials and fallback are unavailable.
- src/openai-usage.mjs keeps legacy openai_requests row bodies/revisions/order and tokens_only summary. A strict records-only v2 Store mode opens the original file with create:false. New openai_request_authorities and openai_authorizations records hold scope/ownership/explicit web authority. Old unowned records project as legacy and cannot be claimed, changed or retried.
- OpenAI promptTokens comes from raw input_tokens, including cached tokens. For input_tokens=11/cache=3, the ledger records 11/3 while pi-ai native usage may report inputTokens=8/cacheReadTokens=3. There is no inferred CNY price.
- Existing DeepSeek limited cumulative CNY 150, web-unlimited authorization, old unknown reservations and balances are unchanged. OpenAI requires a separate explicit web authorization; the development approval never authorizes OpenAI.
- Existing ledger files are mandatory. Fresh creation is an explicit initialization operation, not a fallback when a configured file is missing.

## Required next integration

The implemented v2 composition provides explicit route configuration, independent startup main/Learn choices, installed-module and native-child ownership checks, and a root guard at final dispatch. Remaining integration must combine the separately accepted installer, preserve native main selection and independent daily Learn defaults/run snapshots, and expose authenticated separate web usage/unknown summaries. Output limits remain explicit deployment values; no new daily output-limit UI is implied. It must preserve old OpenAI unknowns and old DeepSeek balances, prove the actual packaged web main/tool/Learn/restart path and model selection readback, and keep user credentials in the native credential service. Whole-goal acceptance and real-provider/user-value claims remain outside these local simulations.
