# DeepSeek 计费接入

当 DSH 准备发送一次模型请求时，Arcfold 先核对这次工作的归属、输入范围和费用授权，再预留最坏费用。请求仍由官方适配器编码，回答与工具调用仍由官方代码解释；Arcfold 保存同一份网络回执并结算，不另建执行循环。

当前是集成开发接口。首轮 31 项受管检查通过，覆盖冻结账本副本、计费、响应中断与恢复、原生请求身份、官方发布包补丁。它们使用本机假服务器或固定脚本，不代表真实 API、正式产品或用户效果已经验收。

## 装配与范围

在全新隔离安装中使用官方 DSH `0.2.2-rc.1` 和[固定发送接口补丁](provider-seam.md)。全局装配 `@arcfold/dsh/deepseek-budget` 与 `@arcfold/dsh/deepseek`，并保留 Arcfold 主插件、官方会话和权限服务。后者只有在补丁文件摘要和实际加载函数的能力标识都正确时才注册 `deepseek-official` 路由，见 [deepseek-provider.mjs](../src/deepseek-provider.mjs) 的 `apply()`。

| 配置 | 要求 |
| --- | --- |
| 账本 | `ledgerPath` 指向原累计账本；`ceilingCny`、`authorizationRef` 与其中现行授权一致。不得创建一份新的实验余额。 |
| 范围 | 每个宿主固定 `scope: limited` 或 `web-unlimited`；网页另提供完整 `webAuthorization`，不由消息、模型或工具参数决定。 |
| 证据 | `artifactDirectory` 为这个宿主专用目录，与另一个宿主分开。插件持有系统文件锁后才恢复，关闭后释放锁。当前实现需要 POSIX 宿主。 |
| 模型政策 | `modelPolicies` 明确每个型号的输入上界、预留输出上界、费率版本和允许的思考强度；可再用 `requestMaxTokens` 限制实际请求。预留不默认把实际 `max_tokens` 当成已证明的供应商硬上限。 |
| 模型连接 | provider 插件明确配置 `apiKeyRef`、`maxTokens`、`reasoningEffort`。凭据引用交给官方凭据服务解析，秘密只在内存用于请求，不进入配置示例或证据。 |

部署时账本与证据目录须提供明确的绝对路径；本包不携带个人路径、旧数据或凭据。正式配置只允许固定官方 Messages 地址；`allowLocalTestEndpoint` 仅用于本机隔离测试。关闭原生未计费 provider、自动标题、压缩和重试等未纳入本次范围的入口，不把未配置发送器的官方默认路径当成替代方案。

首版支持主会话的文本及客户端工具调用、工具返回的文本，包括本地文件读取结果；Learn 使用已通过自身检查的独立原生会话，沿用无工具的学习配置。真实图片、文件附件、文档上传、服务端工具及未知网络字段会被程序拒绝；普通文字里提到“文件”不受影响。

[deepseek-budget-plugin.mjs](../src/deepseek-budget-plugin.mjs) 的 `nativeRequestIdentity()` 只接受唯一归属的主会话或已提交的学习会话，绑定当前尚无结果的原生轮次和步骤，以及已观察到的日志摘要。其他后台用途和独立模型调用不获得计费身份；当前所有显式 `purpose` 都被拒绝。账本持久保存该身份，不新增另一套工作状态。

## 业务库和累计账本

[BudgetLedger](../src/budget.mjs) 在插件中始终以 `create:false` 打开已有账本。路径不存在、既有结构不支持或授权不匹配都会失败；`create:true` 只供新隔离测试库使用。

理解、方法等业务记录使用 [Store](../src/store.mjs) 默认的 `business_meta`。计费使用受限的 `legacy-ledger-v2` 模式，继续旧 `store_meta` 的 schema 2 和写入序号，不创建另一份从零开始的计数。两者必须使用不同数据库；不能让业务 Store 打开计费库，也不导入旧 jobs、租约或 worker。

有限实验继续原 ¥150 累计授权；网页按另一个明确授权不限总额，但仍预留、记账和保留未知费用。迁移不释放原六笔 unknown 预留，不重算旧行、不覆盖历史授权、不把余额重置为 ¥150。恢复只处理新发送器自己的证据与归属记录。账本金额是按冻结费率计算的本地核算值，不冒充已核对的供应商账单。

## 一次请求与恢复

[DeepSeekTransport](../src/deepseek-transport.mjs) 按以下顺序工作：

1. `validateInput()` 在 DSH 转换附件前检查一次，`createTransport()` 在官方准备图片或认证前再检查一次。每个原生步骤只取得一个发送器。
2. `validateWire()` 核最终网络正文、型号、思考强度和输出限制。`send()` 计算实际字节摘要，事务预留费用，保存请求原件，再 `markDispatched()` 并执行一次底层 POST；同一发送器不能重发，HTTP 421 和重定向也不触发第二次发送。
3. 原始响应字节和分片顺序先写盘。[MessagesReceipt](../src/deepseek-receipt.mjs) 只提取费用证据：要求完整结束事件、合法最终用量、无未完成尾部，并严格匹配请求型号；没有隐式型号别名。缓存输入只加一次，当前仅接受明确为零的缓存创建量。
4. 完整回执保存后才 `settle()`，再把结束事件交给官方译码。费用已知但业务内容失败仍应记账；可见正文不等于费用已经完整。中断、缺失用量、型号不符或不合法尾部保持 unknown 预留。
5. `close()` 先停止新请求、取消自有网络，等待正在进行的响应写盘和结算完成。插件随后关闭账本并释放目录锁；取消不能抹除已经收到的确切用量。
6. `recover({exclusive:true})` 在持锁冷启动时核对原请求、原字节、摘要和分片顺序。有完整回执则幂等结算；发送后缺回执则保留未知，不重发；只有确定尚未经过发送门的自有预留可释放。它不修改旧六笔未知，也不回滚累计金额。

响应容量和超时均有明确上界。当前没有多模态、自动费用重试或供应商账单自动对账；正式宿主组合、真实 DeepSeek 调用、产品效果和日常网页迁移仍须分别验证。局部检查与固定脚本成功不能代替这些验收。最终运行身份及证据由受管验证记录补充。
