# 决策：[061-D1] 整理把长工具输出原文和整段学习记录都发给模型

Status: proposed
observed_in_version: 0.7.0 + main@8b432a6（测试版）
fixed_in: pending
user_verified: pending

## 来源

Agent 查看测试版目标树记录里的后台调用用量时发现。数据是测试版的两份目标树记录：2026-11-19 至 11-20 的预览备份，和当前测试版记录（11-21 至 11-22）。Murphy 原话：draft 2345

## 问题

<!-- 谁在什么场景遇到什么，实际发生了什么，证据在哪里。一份决策只写一个问题。 -->
目标完成、离开或超时后，整理环节给这个目标写摘要。它的输入里有两块很大，又基本用不上：

1. 长工具输出原文。学习从交付 025（PR #42）起，把超过 4000 字的工具输出换成一行引用（`compactLearningSource`，`src/tree/experience.mjs:7`）。整理没有用这条规则，冻结输入时直接放原文（`src/tree/consolidation.mjs:37`）。读文件、跑命令的结果整段进了整理输入。
2. 学习记录。整理把被覆盖的每次学习任务的输入（除原文外的全部字段：`knownItems`、`constraints`、`changeReceipts`、`outputBindings`、`previousReceipt` 等）连同输出一起放进 `learningHistory`（`consolidation.mjs:40`）。这些字段是当时的版本，本次整理自己的 `knownItems` 和 `constraints` 里已经有当前版本。

整理要写的是产出、决定、下一步和未定事项。工具调用参数（写了哪个文件、改了什么）、助手回答、用户原话都在，长工具输出的原文很少用得上。

### 实际例子

- 2026-11-21 14:13，一个目标离开后触发整理。发给模型的消息 320,537 字符，计 94,480 输入 token，是这份记录里最大的一次调用。其中 15 条工具输出原文共 266,559 字，`learningHistory` 15,778 字。同一轮的学习输入里，同样这 15 条工具结果只有 41,375 字，因为长输出已换成引用。
- 预览备份里另 4 次整理：工具输出原文占输入的 44%，`learningHistory` 占 19%。

## 方案

1. 整理冻结输入时，对原文用学习同一条规则：超过 4000 字的工具输出换成一行说明，写明字数、原文按引用保留。说明文字改成"未放入本次输入"，不再写"学习输入"；学习那边的说明文字不变。
2. 原文 id 不变，摘要仍然可以把这些工具结果当作来源引用；提交摘要时照旧记完整的原文引用。
3. `learningHistory` 每条只留：任务号、当时这一轮的 `currentTurn` 和原文 id 列表、模型输出、回执，以及作废标记和原因。去掉当时的 `knownItems`、`constraints`、`changeReceipts`、`scope`、`allowedIds`、`outputBindings`、`previousReceipt` 和 `nativeLogRef`。
4. 主对话的压缩也走整理环节，但它的输入另外组装（`src/tree/runtime.mjs:605`），提示里要求保留工具结果，本条不改。

## 预期效果

按记录里的实际任务重新生成：

- 14:13 那次整理，输入从 310,014 字符降到约 74,918 字符，少 76%。
- 预览备份 4 次整理，分别少 27% 到 44%。
- 再加上 060（只把模型要读的字段发给模型），这 5 次整理一共少 39% 到 87%。

## 考虑过的其他做法

<!-- 只写真实考虑过的做法和放弃的原因。 -->
- 整理里的工具输出全部去掉，连短的一起：短输出常是测试过没过、命令成没成功，摘要里的产出和状态可能要靠它，不采用。
- 把阈值从 4000 字调低：没有数据说明 1000 到 4000 字的输出用不上，先跟学习保持一致。
- `learningHistory` 保留当时的 `constraints`，让模型看到当时的背景：整理按当前背景写摘要，提示词里也没有要求对照旧背景，不保留。

## 验收标准

- 模型拿到的工具和原版 DSH 一致：未安装 Arcfold 时用 standard 取原版完整工具基准；安装后 arcfold-main 核对 bash、read、write、edit、glob、grep（Arcfold 会关闭 standard）。实际会话 request/header 与模拟服务收到的清单均须核对，缺项判失败。

- 测试：整理输入里超过 4000 字的工具输出换成说明，原文 id 不变；摘要引用这个 id 能通过核对，提交后的摘要记的是原来的完整引用。
- 测试：4000 字以内的工具输出、工具调用参数、助手回答、用户原话原样保留。
- 测试：`learningHistory` 每条只有上面列的字段；被作废的学习记录照旧带作废标记和原因。
- 测试：学习输入里的省略说明文字和以前逐字相同。
- 测试：主对话压缩的输入不变。

## 风险

- 如果某个目标的产出只出现在一段长工具输出里（比如助手读出一份长文件，回答里只说"见上"），摘要可能没有原来具体。整理不带工具，模型没法自己去查原文。上线前用测试版回放对比几次摘要。
- 对已经冻结的整理任务不起作用，只影响之后新冻结的任务。
