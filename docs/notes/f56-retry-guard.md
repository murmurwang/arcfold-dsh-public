# 决策：[084-D2] 断线自动重试后整轮报错退出

Status: proposed
observed_in_version: 0.8.0 预览（第 4 次候选），测试版装 main
fixed_in: pending
user_verified: pending

## 来源

开发者反馈 F56（2026-11-23 登记，附 4 张截图）。Murphy 原话：两个都开。专项结论见 requests/f56-speed/findings.md。

084-D2 曾改为“不自动重发、中文说明加手动继续”。Murphy 对 084-A1 的原话：084-A1 放宽规矩，允许自动重发。本版恢复 084-D1 已展示并对齐的自动重试方案，方案、范围和验收与 D1 相同。

## 问题

Murphy 在测试版里聊着聊着，界面出现「已重试模型请求（1/5）」，紧接着「本轮运行失败 No live unattempted native step（UNKNOWN）」，这一轮就停了。

会话记录（测试版 session-ba051ebd…）里的顺序是：第 2 步开始 → 第一次请求因连接被重置（ECONNRESET）以错误结束 → DSH 按自己的重试策略发起第 1 次重试 → 重试还没发出就被拦下 → 整轮结束。测试版另有两个会话出现过同样记录。

拦下它的是 `src/tree/model-owner.mjs` 的 `nativePosition`：每次发请求前，它要求这一步开始之后还没有任何 `assistant/attempt`。DSH 的自动重试会在同一步里留下前一次失败的 attempt，所以只要断一次线，重试一定被拒。日常 0.8.0 里这段代码完全一样，任何用户网络抖一下都会碰到。077 修的是同一场景下的另一道核对（主对话上下文快照），这次是它后面的一道。

## 方案

1. `nativePosition` 区分两种情况：这一步里之前的 attempt 都以错误结束、没有产生 assistant 消息，并且后面跟着 DSH 的 `llm/retry-started`，就当作同一步的重试放行；其余情况（已经有回答、步骤已结束、轮次对不上）照旧拦下。
2. 重试沿用同一个请求身份：位置相同、请求内容哈希相同、原记录仍是 admitted 时，`admitInvocation` 已有的复用分支直接返回原记录，不新建，也不计成第二次调用。请求内容变了仍拒绝。
3. 主对话、学习、检验等后台角色都走同一条路，单次调用上限按「一个位置一次」不变。

## 预期效果

- 断线后 DSH 自动重试能接着跑完这一轮，用户不用手动点继续，也不再看到这句英文报错。
- 已经回答过、或者请求内容被改过的情况仍然拦下。

## 考虑过的其他做法

- 关掉 DSH 的自动重试：等于让用户每次断线都手动继续，体验更差。
- 去掉这道核对：它防的是同一位置被发两份不同请求，不能去掉。
- 每次重试新建一个请求身份：会让账单和调用上限把一次重试算成两次，后台角色还会撞上一次调用的限制。

## 验收标准

- 模型拿到的工具和原版 DSH 一致：未安装 Arcfold 时用 standard 取原版完整工具基准；安装后 arcfold-main 核对 bash、read、write、edit、glob、grep（Arcfold 会关闭 standard）。实际会话 request/header 与模拟服务收到的清单均须核对，缺项判失败。
- 自动测试：模拟服务第一次请求返回连接重置、第二次正常，主对话这一轮正常完成，tree_invocations 里这个位置只有一条记录。
- 自动测试：学习任务同样场景能完成，不触发单次调用上限。
- 自动测试：同一步已有 assistant 回答、或重试时请求内容变了，仍然拦下。

## 风险

- 依赖 DSH 事件里 `assistant/attempt` 的错误标记和 `llm/retry-started` 的格式；DSH 升级改了格式会退回到全部拦下，测试里要固定这两种事件的样例。
- 这是产品仓库“不要自动重发结果未知的请求”的一个例外，由 Murphy 在 084-A1 选择放宽：只限断线后 DSH 对同一步、同一请求内容的自动重试。断线时第一次请求可能已经到达服务商并计费，只是回来的路上断了，自动重发就会再计一次费，同一步最多按 DSH 的重试上限（5 次）重复计费。不额外处理。
