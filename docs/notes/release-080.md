# 决策：[068-D1] 把主分支上尚未发布的 13 项改动打包为 0.8.0

Status: proposed
observed_in_version: 0.7.0
fixed_in: 0.8.0
release_source: 2ee885038e5e3abf9b614d7c7c940352b1476d2a
summary: Arcfold 新增常驻目标面板，能在对话中更准确地调整目标，离开目标时会整理经历，并减少重复发给模型的内容。
user_verified: pending

## 来源

2026-11-22 核对 GitHub 正式标签、主分支历史和 npm 的两份包：当前正式版 0.7.0 对应 `69f33d1`，其后主分支新增 #60–#72，共 13 项合入；两份包的最新版仍是 0.7.0。

## 问题

从 npm 安装或更新的用户仍只能拿到 0.7.0，无法用到已经合入的目标面板和近期修复。主分支有代码不等于安装包已经发布。

## 方案

用 #72 合入后的 `main` 定版 0.8.0。发行提交只整理版本、依赖记录、更新日志和已收录的更新说明，不夹带功能修改。按原流程提交发行 PR、等待自动检查并受管合入，随后以合入提交制作核心包和界面包。本次不另启付费审阅，按仍生效的暂停记录逐项核对合入依据和发布前待办。

| PR | 收入本版 |
| --- | --- |
| #60 | 常驻目标面板，展开可看完整目标链。 |
| #61 | 主助手区分目标与眼前动作，并能把目标放到合适的上级。 |
| #62 | 离开目标后整理经历，改名后刷新概况。 |
| #63 | 一个目标整理出错时，后台继续处理其他目标。 |
| #64 | 公开 README 对齐此前正式版 0.7.0；这是文档项，不是运行改动。 |
| #65 | 退出时被打断的学习重启后可恢复：未发出则重做，已发出但无结果则跳过。 |
| #66 | 补上已发出请求、从会话日志确认因退出而结束的恢复路径，不重复发送。 |
| #67 | 整理目标时，可把挂错的下级目标挪到正确的上级。 |
| #68 | 提示写明一句概况最多 60 字，避免因写长报废整次整理。 |
| #69 | 整理时不再反复发送长工具输出和整段学习记录。 |
| #70 | 后台只把模型需要读的字段发给模型，程序仍保留核对所需信息。 |
| #71 | 同一目标下保留旧编号表、在后面追加新表，避免每轮改写旧内容导致模型服务商不能复用缓存。 |
| #72 | 改名、新建子目标、加上层目标或切换目标时，容许模型多带一个空的上级字段。 |

## 预期效果

用户从 0.7.0 更新后，可在输入框上查看完整目标链，在对话中调整目标，离开后按新规则整理。旧目标和对话应保留；真实模型下的回答质量和节省幅度不由模拟测试推断。

## 考虑过的其他做法

<!-- 只写真实考虑过的做法和放弃的原因。 -->
- 只发 11 月 22 日太平洋时间当天合入的 PR：会漏掉尚未正式发布的较早改动，主分支定版也不会把它们自动排除。
- 继续使用本机在 0.7.0 上叠加主分支的体验方式：不会让其他用户下载到新版，也不能代替对原始安装包的验证。

## 验收标准

- 模型拿到的工具和原版 DSH 一致：未安装 Arcfold 时用 standard 取原版完整工具基准；安装后 arcfold-main 核对 bash、read、write、edit、glob、grep（Arcfold 会关闭 standard）。实际会话 request/header 与模拟服务收到的清单均须核对，缺项判失败。

- 对照 0.7.0 标签，确认定版清单恰为 #60–#72，核心包、界面包和依赖记录版本一致，两次构建所得原包逐字节一致。
- 用已授权的独立测试账户和本机模拟模型，验证首次安装、从 0.7.0 更新、合成对话、下载失败后恢复、刷新及重启读回；保存同一对原包的逐项回执。不触碰日常资料或凭据。
- 不自动切换日常安装。构建出原包后，按流程单独申请日常预览；装入预览、隔离验收和发布前待办均满足后，再开绑定同一候选和两份包校验值的正式发布单。未明确答复正式发布单，不建发布标签、不公开 GitHub Release、不向 npm 暂存或上传。

## 发布前待办

- 在这一版原包中确认目标面板可见，展开后显示完整目标链，并高亮当前目标。
- 在这一版原包中确认对话离开目标后，旧目标在自己的学习完成后触发整理；留存对应目标和整理结果。
- 在这一版原包中确认主助手带空上级字段改名时，目标改名成功且上级不变。

## 风险

0.7.0 曾在独立账户出现升级后模型选择未实际生效、读回未确认；本次不沿用旧版例外。固定测试未覆盖的发布前行为另取本候选的证据，无法核对就记未确认并停下，不以构建成功或主分支覆盖体验替代。
