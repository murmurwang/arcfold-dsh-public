## 来源

交付 045 的修复 PR #58 已合入 main（afa5633）。0.7.0 第 2 次候选在日常预览中按 042-A6 核对时发现问题，见反馈 042-F1。

## 问题

0.7.0 第 2 次候选的"当轮修改目标"里，switch 只要带 name 字段就拒绝。日常对话里 gpt-6.1-sol 两次切换都带了 name（原名、空字符串），都被拒绝，目标没切成。这个包不能公开。

## 方案

以当前 main afa5633 为源码，重新定版 0.7.0，两份包版本不变，生成第 3 次候选。

发行工具会把 main 上全部尚未发行的更新说明一起收进来，不能只挑 #58。所以这次除了 #58，还会带上第 2 次候选之后合入的另外三项：

- PR #54（交付 043）：CI 里 Desktop 检查拆成两路并行。只改 CI，不进安装包的运行代码。
- PR #56（交付 040）：每次启动自动记录 Arcfold 各步用时，写到本机 startup-timings.jsonl。
- PR #57（交付 047）：取对话里的一条来源时不再复制整个对话。

这三项都已正常合入 main、CI 通过（审阅按 026-A3 暂停）。版本说明在原 0.7.0 条目里追加，不重复已汇总的内容。

## 预期效果

第 3 次候选里切换到已有目标时带原名或空名不再报错。装进日常预览后，042-A6 的两项（改目标、连续五轮）在新包上重新核对。

## 考虑过的其他做法

- 只带 #58，另外三项留到 0.7.1。放弃原因：同版本修补必须用当前 main 作源码，发行工具会收入全部未发行的说明，做不到只挑一项；要只带 #58 就得先把另外三项从 main 回退，代价更大。
- 把 0.7.0 第 2 次候选直接发出去，修复放 0.7.1。放弃原因：已知切换目标在日常模型下走不通，且 042-A5 的核对还没过。

## 验收标准

- 模型拿到的工具和原版 DSH 一致：未安装 Arcfold 时用 standard 取原版完整工具基准；安装后 arcfold-main 核对 bash、read、write、edit、glob、grep（Arcfold 会关闭 standard）。实际会话 request/header 与模拟服务收到的清单均须核对，缺项判失败。
