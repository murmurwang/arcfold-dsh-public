# 决策：[045-D1] 主助手切换到已有目标时带了名字，切换被拒绝

Status: proposed
observed_in_version: 0.7.0
fixed_in: pending
user_verified: pending

## 来源

开发者反馈 042-F1（2026-11-20 登记，附截图），发生在日常 DSH 装上 0.7.0 第 2 次候选预览之后，按 042-A6 核对当轮修改目标时。Murphy 原话：开修复任务。

## 问题

日常 DSH 的申请计划对话（会话 session-77e73834，第 30 轮，模型 gpt-6.1-sol (lmu)）。用户说"改一下目标"。主助手判断应切换到已有目标"盘点申请所需的结果、已有证据与缺口"，调用了两次 arcfold_revise_goal，op 都是 switch：

- 第一次带了 `name: "盘点申请所需的结果、已有证据与缺口"`，也就是目标原名。
- 第二次带了 `name: ""`。

两次都返回 `switch uses an existing goal and takes no name`。主助手最后回复"切换工具报参数错误，尚未切换成功，需要你在界面中选中这个已有目标"。目标树里这一轮没有任何修改记录。

原因在 `src/tree/tools.mjs:63`：switch 只要参数里有 name 字段就拒绝，不管内容。工具定义里 name 是选填，但 gpt-6.1-sol 两次都填了，被告知报错后也只是改成空字符串，没有去掉这个字段。所以用这个模型时，"切换到已有目标"基本走不通。rename、create_child、add_parent 需要 name，不受影响。

## 方案

switch 收到 name 时，不再一律拒绝：

1. name 为空字符串，或去掉首尾空白后与目标原名相同：当作没填，照常切换。
2. name 与目标原名不同：仍然拒绝，报错改成说明"switch 不改名，可以不填 name；要改名请切换后在下一轮用 rename"，让模型知道怎么改。
3. 工具说明里 switch 那句补上"不填 name"。

切换的生效时间、范围检查（只能切到已有候选目标）、版本检查都不变。

## 预期效果

用同样的调用（带原名或空名）时，switch 成功，本轮回答结束后转到目标，回复里说明改成了什么。带不同名字时，模型从报错里知道该去掉 name 重试。

## 考虑过的其他做法

- switch 一律忽略 name。放弃原因：模型如果想"切过去并改名"，名字被悄悄丢掉，回复里说的和实际不一致。
- 把 switch 拆成单独的工具，不带 name 参数。放弃原因：工具清单要变，改动和验收面都更大；问题只是校验太严。
- 只改提示词让模型别填 name。放弃原因：截图这轮模型已经看到报错文字还是填了空字符串，只靠提示不可靠。

## 验收标准

- 模型拿到的工具和原版 DSH 一致：未安装 Arcfold 时用 standard 取原版完整工具基准；安装后 arcfold-main 核对 bash、read、write、edit、glob、grep（Arcfold 会关闭 standard）。实际会话 request/header 与模拟服务收到的清单均须核对，缺项判失败。

- switch 不带 name、带空字符串、带目标原名（含首尾空白）都能成功，记为 pending 并在回答结束时生效。有测试。
- switch 带不同名字被拒绝，报错里写明不填 name 或切换后用 rename。有测试。
- 切到非候选目标、当前目标、已删除目标、版本已变的目标仍被拒绝。035、038 原有的修改目标测试全部通过。
- 日常观察（不作为发布条件，单独记录）：在 0.7.0 新候选预览里，让主助手切换到一个已有目标，看是否切换成功并在下一轮从该目标开始。

## 风险

- 名字比较只做去首尾空白后的完全相同；模型填了近似但不完全一样的名字时仍会被拒，要靠新的报错文字让它重试。
- 这是 0.7.0 未公开前的同版本修补：合入后要打第 3 次候选，重新装日常预览，旧候选的预览授权和证据不能沿用。
