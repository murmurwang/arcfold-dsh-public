# Agent Note: 组合 Arcfold DSH 0.4.0 首发与通用交付流程

Status: proposed
observed_in_version: 0.3.2、0.3.3、0.3.4（DSH 0.2.2-rc.1）
fixed_in: 0.4.0
user_verified: pending

## Source

Murphy 于 2026-11-14 确认的 Arcfold DSH 工作流及首发要求。代码来源是现有私有仓库的 #8、#9，以及针对原版 DSH 测试的后续文件子进程修复。待发布的新包仍须在普通测试账户验收。

## Problem

早期本机包能安装和更新。0.3.2 和 0.3.3 在计算消息长度时无法载入计数库。0.3.4 自带计数环境后，原版 DSH 仍在读取工作区时因文件子进程启动失败，在模型收到请求前中断。修复后的 0.3.6 和 0.3.7 已在原版 DSH 的普通测试账户完成模拟对话、更新和重启读回。现有 #9 缺这项文件修复，也缺与该提交对应的 GitHub 检查。交付入口尚无法对任意登记的提案执行独立审阅、合入、构建及回写。

## Proposal

以私有 GitHub main 为基线，整合 #9 已包含的计数环境和可移植检查，以及 0.3.6 和 0.3.7 已使用的文件子进程修复。核心包和界面包使用同一个 0.4.0 版本，DSH 兼容版本固定为 0.2.2-rc.1。让 GitHub 对新提案的确切提交执行 macOS 检查。将通用入口、审阅提示、发布与本机复测脚本纳入仓库。独立审阅使用专用 OpenAI 项目的新请求，并记录两侧提交、检查和证据。

## Expected outcome

从明确版本的源码可以重建相同的安装包。普通测试账户从新资料开始，可以按包名安装、发送一轮合成消息、主动更新并重启读回。后续提案可以沿同一路径登记、审阅、合入和发行，每条用户观察都能追到原问题和安装版本。

## Alternatives considered

- 继续使用 #9。它已有计数修复，但没有处理后来在原版 DSH 复现的文件子进程失败。
- 把签名宿主的整套环境交给子进程。它会扩大子进程能读取的环境。修复所需的是给同一个宿主的受管 Node 子进程保留启动模式。
- 直接用 GitHub 地址作为首发入口。DSH 的版本更新区块依赖注册表来源，所以按 Murphy 已确认的包名安装，GitHub 地址作为单独复测项。

## Acceptance criteria

- GitHub 自动检查实际检出并通过新提案的确切提交，覆盖离线对话、打包、数据和工作流主要拒绝条件。
- 发布入口核对两侧提交、通过的检查和新启会话的独立回执。0.4.0 核心包与界面包可重建，记录归档摘要、兼容范围、许可与更新说明。
- 隔离验收从新数据开始，实际在 DSH 插件页按包名安装、发消息、选择更新、重启读回同一正文并验证下载失败恢复。GitHub 安装和版本区块另留结果。
- 正式发布经所需授权，Murphy 从自己的插件页输入包名安装。后续把已确认的用户观察登记回原问题。

## Risks

先前原版界面实测对应 0.3.6 和 0.3.7，0.4.0 实际归档仍要验收。首次公开前需要逐文件筛查源码并核对第三方来源与许可。专用审阅一次最高 3.50 美元，真实运行前报告估算。Desktop 新资料与 4397 独立。
