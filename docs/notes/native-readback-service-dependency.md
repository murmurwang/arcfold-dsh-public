## 问题

在升级前已有的会话中选择 GPT 后，服务端会话记录和补读结果均为 GPT，页面仍显示 DeepSeek。新采集的页面报错为 `cannot get property "remote" without inject`，调用来自选模监听绑定函数，并导致输入区目标面板及回合末入口渲染失败。

源码 `packages/method-ui/src/native-model-readback.mjs` 的监听绑定使用 `owner.remote.session`，却只声明了 `remote.session`，漏掉它所属的 `remote` 服务。真实 DSH 要求先声明需要使用的服务，才允许页面代码访问。之前的本地测试把服务直接放在共同根环境，绕过了真实插件之间的访问限制，因此未发现这个错误。改为由另一个插件提供服务后，现有代码可在本机稳定重现同一句报错。

## 方案

- 补齐选模监听所用原生服务的依赖声明，使监听能在真实插件环境启动；仍按 072-D2 的成功保存、单次补读、原生接收、顺序和连接有效性检查运行。
- 将本地接线测试改为由独立插件提供原生服务，复现真实访问限制，并保留晚到依赖、会话替换、失败保存、旧结果迟到等覆盖。测试必须证明现有缺声明的写法失败，补齐后可完成真实原生目录与页面状态接收流程。
- 仅修改选模读回文件、对应测试、说明和更新说明。任务登记的发行元数据路径本次不修改。先从当时 GitHub main 开普通功能修复 PR，相关本地检查后交 CI，按 026-A3 继续暂停付费审阅，通过后受管合入。
- 修复合入后再准备新的 0.8.0 发行决策。目前主线还合入了 #82（修正切换目标时版本核对对象）和 #83（请求定稿前刷新变化的目标背景）；新发行会明确列出这些已有修复与本修复，按实际源码再次对齐，不自动带入其他产品改动。

本次工程费用 0 美元，不发真实模型请求，不改日常环境、配置、凭据或已有候选原包。预览安装和正式发布仍按新候选的两份实际包分别授权。

## 预期效果

选模监听不再因漏声明服务而启动失败，已保存模型能按原方案读回页面；目标面板不会再因这处错误而被移除。真实窗口是否全部恢复，必须用后续新候选原包验证，不能用测试通过代替。

## 考虑过的其他做法

- 继续重跑候选 2：原包内的声明错误不变，重复运行不能修复。
- 绕过访问检查直接取服务，或把点击值写进界面：会绕开原生生命周期及真实保存结果，不采用。
- 回退 #80：会撤掉读回机制，原会话的旧模型显示问题仍存在。

## 验收标准

- 独立插件提供服务的回归能重现旧声明报错；新声明完成选模后的单次补读、原生状态接收和显示更新。
- 保存失败不补读，迟到结果不能覆盖后来的选择，会话替换、连接变化或卸载后不继续写页面；既有相关检查通过。
- CI 通过并完成受管合入；不把它记成原包验收通过。
- 后续发行原包必须重新完成普通账户完整验收，包括升级前原会话选模型及推理等级、下一条模拟请求、配置刷新、重启读回、安装和失败恢复。

- 新候选的三项既有功能待办继续保留；没有证据就记 unconfirmed，不沿用旧候选的通过或豁免。
