# 决策：[034-D1] 将目标归属判断的等待上限延长到 60 秒

Status: proposed
observed_in_version: 0.6.0
fixed_in: pending
user_verified: pending

## 来源

0.6.0 本地使用中出现了连续两轮目标归属超时。相同的一行改动已用于本地试用。

## 问题

用户发送消息后，目标判断超过 12 秒会被取消，这一轮随即按默认归属继续。稍晚返回的判断无法再为本轮创建目标。

## 方案

从 GitHub 主分支开独立开发目录，只把目标判断的等待上限由 12 秒改为 60 秒，同步已有测试中的等待时长和变更说明。模型提前返回就立即继续。此次交付为产品源码 PR，开发和检查使用独立目录。

## 预期效果

给超过 12 秒但在 60 秒内返回的有效目标判断留出处理时间。实际创建什么目标、学到什么，由本轮模型结果决定。

## 考虑过的其他做法

继续只在本地试用可以观察真实对话，但其他安装无法通过后续版本取得这项改动。

## 验收标准

- 核对配置给定时器的上限为 60000 毫秒，运行现有归属测试验证正常返回、超时回退和迟到结果处理。
- 提交时使用独立开发目录。保留正在使用的本地安装和运行中的对话。

## 风险

如果目标判断持续没有返回，用户最长会比以前多等约 48 秒才开始主回复。
