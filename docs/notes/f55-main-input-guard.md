# 决策：[077-D1] 主对话断线重试后被发送前核对拦下

Status: proposed
observed_in_version: 0.8.0 预览（第 1 次候选）
fixed_in: pending
user_verified: pending

## 来源

开发者反馈 F55（2026-11-23 登记，附截图）。

## 问题

Murphy 在日常 0.8.0 预览里用一个长会话（77 轮、约 6960 万 token）写 Arcfold 介绍。中间连续几轮报 Connection error，他每次点「继续」。最后一次继续后，模型正常做完分析、读了一个文件，下一步就停了，界面显示：

> 本轮运行失败 Main requires its current trusted context and user-turn guard（UNKNOWN）

这句话来自 `src/tree/model-owner.mjs` 的 `assertProjection`。主对话每次发请求前，会调用 `src/tree/runtime.mjs` 的 `verifyMainInput` 做一次核对，只要它返回的不是 `true`，这一轮就直接失败。它依次查这几样：

1. 这个会话挂着主对话，当前范围是 active，范围对应的回合就是这个任务的回合，分派版本也对得上；
2. 这一轮用户原话还在请求里，并且内容没变；
3. 发送前重新算出的树上下文快照，和这一步开始时挂上去的快照是同一个（`snapshotKey` 一致）；
4. 请求里的树上下文消息，和挂上去时的一模一样。

现在的问题有两层：

- 哪一项没过不知道。`verifyMainInput` 只返回 false，所有原因都合成同一句话；本机 `~/.dsh/sessions` 和 `tree.sqlite` 里都没留下这次失败，事后查不出来。
- 用户看到的是一句英文和 UNKNOWN，也不知道接下来该怎么办，再点继续能不能好。

对原因的猜测（未证实）：快照是在每一步开始（`agent/pre-step`）时算的，真正发出去前又重算一遍。两次之间如果树有变化，比如后台学习环节、别的会话写入了节点概貌，或者断线后传输层重试没有重新走 pre-step，第 3 项就会对不上。连续断线让这个时间窗口变长，所以更容易撞上。需要先拿到记录才能确认。

## 方案

分两步，同一个 PR 里做：

1. 记下原因。`verifyMainInput` 改为返回具体是哪一项没过（范围／回合／分派版本、用户原话、快照、树上下文消息），失败时把这个原因和会话号、回合号、两边的 snapshotKey 一起写进现有诊断记录（不包含消息正文）。界面报错保留原有错误码，把原因换成一句中文。
2. 修掉能证实的那一类。先用测试复现「断线重试 + 中途树变化」这个场景。如果确认是快照在 pre-step 和发送之间变了，就在发送前遇到这种情况时重新挂一次当前快照再核对，而不是整轮失败；其他几项（回合换了、用户原话不在）属于真的不该发，仍然拦下，只把提示改清楚。

如果复现后发现原因不是快照，第 2 步按实际原因改，改法变了就先修订本决策给开发者看。

## 预期效果

- 断线后点继续，树在中途有更新时，这一轮能接着跑，不再报这个错。
- 真的不该发出去的情况仍然拦下，但界面会用中文说明是哪一项不对，日志里能查到。

## 考虑过的其他做法

- 只加日志不改行为：下次还会打断用户，只是能查原因。放弃，因为快照变化这一类有安全的处理办法。
- 去掉第 3、4 项核对：这两项防的是模型看到过期或被篡改的上下文，不能去掉。
- 失败后自动整轮重试：会重复执行已经做过的工具调用，风险比重新挂快照大。

## 验收标准

- 模型拿到的工具和原版 DSH 一致：未安装 Arcfold 时用 standard 取原版完整工具基准；安装后 arcfold-main 核对 bash、read、write、edit、glob、grep（Arcfold 会关闭 standard）。实际会话 request/header 与模拟服务收到的清单均须核对，缺项判失败。
- 自动测试：模拟连接错误后继续，并在 pre-step 和发送之间改动当前节点概貌，这一轮正常完成，请求里的树上下文是最新快照。
- 自动测试：回合已被替换、或用户原话不在请求里时，仍然拦下，诊断记录写明具体哪一项，界面报错是中文说明。
- 诊断记录里不出现消息正文。

## 风险

- 发送前重新挂快照，会让同一步里模型看到的上下文比 pre-step 时新。需要确认工具调用和曝光记录（`expose`）用的是重新挂之后的快照，不会出现记录和实际不一致。
- 原因还没证实。如果复现不出来，第 2 步可能只能先交付第 1 步，等下次出现时再根据记录修。
