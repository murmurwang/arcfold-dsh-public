# 决策：[067-D2] 子目标学到的认识留在子目标，上级用不上

Status: proposed
observed_in_version: 0.7.0；源码基线 2ee8850
fixed_in: pending
user_verified: pending

## 来源

公开源码中可以复核的行为，基线为 2ee8850。

## 问题

子目标结束后，整理可以把仍适用的理解或方法放到上级目标，但模型可以跳过所有条目的适用范围判断。回到上级工作时，主助手能看到子目标的摘要，却无法读到留在子目标里的条目原文。

## 方案

只改离开、完成时的整理（不含达到阈值的整理）。

1. 整理输入里本节点自己的有效理解和方法，模型要逐条给出判断：放进 broaden 提到某个祖先，或放进新增的 kept，写一句为什么只对这件事成立。根节点没有上级，不要求。
2. 提示改为要求逐条判断，并说明标准：这条认识离开这件具体的事仍然成立，就提到需要它的最近祖先；适用场景写得窄，不等于内容只在这里成立。
3. 程序核对覆盖情况：没被判断的条目按留在原处处理，记一条带整理任务号和条目编号的诊断，摘要照常保存，不让整次整理作废。
4. 提升仍走现有 broaden 的校验和写入：只能提到祖先，受用户保护、来源不明的不提升；之后检验可以按效果收窄或撤回。

## 预期效果

- 离开或完成子目标时逐条判断理解和方法的适用范围。提升到上级后，在上级或同一上级下的相关目标继续工作时，主助手可以读到条目原文。
- 模型调用次数不变，整理的输出多几行。

## 考虑过的其他做法

- 上级节点的背景里直接列出所有子目标的理解和方法：每轮输入随子目标数量变长，也分不清哪些只对子目标成立，不采用。
- 只改提示、不加 kept 和覆盖核对：这次的问题正是"可以建议"时模型不判断，只改措辞无法知道它有没有逐条看过，不采用。

## 验收标准

- 模型拿到的工具和原版 DSH 一致：未安装 Arcfold 时用 standard 取原版完整工具基准；安装后 arcfold-main 核对 bash、read、write、edit、glob、grep（Arcfold 会关闭 standard）。实际会话 request/header 与模拟服务收到的清单均须核对，缺项判失败。

- 测试：离开触发的整理，本节点有两条有效理解，输出一条 broaden、一条 kept：前者移到指定祖先，后者留在原处并保存理由。
- 测试：输出漏掉其中一条：摘要和另一条的处理照常保存，漏掉的留在原处，留下带整理任务号和条目编号的诊断。
- 测试：达到阈值的整理仍要求 broaden 和 kept 为空。
- 测试：根节点的整理不要求逐条判断。
- 测试：broaden 指向非祖先、受用户保护或来源不明的条目，仍按现有规则拒绝。
- 测试：提升后的下一轮，在上级节点工作的主助手输入背景里包含该条目原文。

## 风险

- 模型可能提升过多，把只对一件事成立的做法推广出去。提升只到祖先，之后检验按"连续没有适用机会"会收窄或撤回，用户也能在界面移回。
- 整理输出变长，可能更容易超长或不合格式。kept 只要求一句理由，漏判不作废整次输出。
