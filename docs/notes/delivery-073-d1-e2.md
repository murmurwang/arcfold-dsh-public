## 来源

交付 068 的第一次候选保留了源码、两份原包及各次失败证据。最新普通账户真实窗口核对证明：GPT 已写入会话且服务端读回正确，页面仍显示 DeepSeek；升级后第二条消息、刷新和重启读回未执行。交付 072 按已对齐修订方案实现修复，PR #80 的两路 GitHub 全量检查通过并已受管合入。

当前 main 为 `0bc55e79ba9eba5952afa0e35926502e1fcdafb3`。原候选之后还已有 #74–#79 六项功能，这次必须明确纳入范围，不能把重打包说成只含选模修复。

073-D1 对齐后，#79 在发行 PR #81 检查期间合入了主线。#81 的原提交两路检查通过，但合入入口发现主线前进，已停止在外部合入写入之前。本次只新增选择 #79 并前移基线；原任务和 PR #81 保留，重新生成发行提交并重跑检查。

## 问题

已安装的第一次候选缺少页面读回修复，原包仍不满足发布条件。修复进入主线不等于已经制作或验证新的安装包，也不表示已经获得新候选的日常安装及正式发布授权。

## 方案

采用未发布版本的同版本修补流程，仍准备 0.8.0，原候选和失败记录完整保留。保留原版 #60–#72 的十三项内容，在上述 main 基线上新增以下七项，生成下一次候选：

| PR | 本次新增范围 |
| --- | --- |
| #74 | 检验发现有依据的漏记时，补入对应目标背景，相同内容只补一次。 |
| #75 | 方法的自查提醒随下一条用户消息交给助手。 |
| #76 | 子目标中其他工作也适用的认识，经整理判断后可带回合适的上级。 |
| #77 | 理解围绕当前目标形成，并可在原条目上继续推进，保留旧版本和依据。 |
| #78 | 学习发出前失败或目标位置改变时恢复，已发出的学习仍不重发。 |
| #79 | 学习时，明确属于另一项已有目标的认识或方法可以直接放到那里；保留原轮次和理由，每轮最多两条，目标无效时留在本轮目标。 |
| #80 | 原生选模成功后补读真实会话状态，让页面跟上已保存选择。 |

发行提交只汇总这七份新增更新说明，统一版本和更新日志，不夹带功能修改；此前十三份说明不重复消费。沿用 0.8.0 原版本的一句话介绍，并追加本次修补内容。走独立发行 PR、自动检查、既有暂停付费审阅规则及受管合入；两份包各构建两遍，核对逐字节一致、许可和公开内容，再用新原包重新做隔离验收。

若主线后来增加其他产品改动，不自动收录，先修订范围并重新对齐。固定隔离测试继续只用本机模拟模型。预计新增费用 0 美元，真实模型请求为零。

本单只对齐重做范围。新包制作完成后，按实际对象另开日常预览授权；日常装入本候选预览、隔离验收和发布前待办全部满足后，再开绑定同一候选与两份包校验值的正式发布授权。主线覆盖体验不能替代原包验证。

## 预期效果

新候选包含原版内容及上述七项新增改动；原会话的模型及推理等级选择能在页面、持久记录和下一条实际请求中一致，并在刷新及重启后保留。真实模型下的回答质量及长期学习效果仍以实际反馈为准。

## 考虑过的其他做法

- 继续发布第一次候选：已知失败仍存在，不能放行。
- 仅把 #80 放回旧源码：需要另外维护分支并对重新组合的代码完成合入与检查；当前建议明确选择现有主线的七项新增改动。
- 升到另一个版本号：0.8.0 尚处候选阶段，同版本修补已能保留完整前后关系。

## 验收标准

- 定版清单相对第一次候选恰为 #74–#80；两份包与依赖记录版本一致，源码和实际包内容相符，两次构建逐字节一致。
- 在新候选原包上重新完成普通账户的首次安装、从 0.7.0 更新、失败下载恢复、升级前原会话选择模型及推理等级、下一条模拟请求、配置刷新和完整退出后重启读回；保留原对话和目标。
- 用未安装 Arcfold 的 standard 会话取原生工具基准，安装后的 arcfold-main 核对 bash、read、write、edit、glob、grep，实际请求头与模拟服务清单一致，缺项判失败。
- 旧候选的所有失败及未确认不迁为新候选的通过。发布前待办只能依据新候选的两份原包记录；缺证据就保留未确认。

## 发布前待办

- 在这一版原包中确认目标面板可见，展开后显示完整目标链，并高亮当前目标。
- 在这一版原包中确认对话离开目标后，旧目标在自己的学习完成后触发整理；留存对应目标和整理结果。
- 在这一版原包中确认主助手带空上级字段改名时，目标改名成功且上级不变。

## 风险

#80 目前通过的是本地及 GitHub 模拟检查，尚未在新候选的原版桌面窗口验证。新增六项功能有各自的合入与检查证据，不等于已证明真实使用效果。第一次候选的三个功能待办仍未确认，新包必须取得自己的证据。本决策不沿用 0.7.0 的豁免，也不授权改动日常资料、配置或凭据。
