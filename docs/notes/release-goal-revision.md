# 决策：[037-D1] 发行包括当轮修改目标、延长目标判断时间和仓库清理的新版本

Status: proposed
observed_in_version: 0.6.0
fixed_in: 0.7.0
release_source: ba25d77a1f5ab2e08e523fa7234cb435430dee0a
user_verified: pending

## 来源

0.6.0 已公开发行。从 0.6.0 到 PR #50 合入后的主分支，共有 #49、#48、#34、#50 四项合入。

## 问题

0.6.0 在回答开始前判断本轮目标。对话中才明确的新目标要到后面才能反映，模型判断超过 12 秒时也会提前回退。公开仓库还保留了一份已转到本地维护的开发工具。

## 方案

以 PR #50 合入后的源码准备两份安装包。建议版本号为 0.7.0，因为这次新增了在对话中调整目标的能力。发行 PR 正文用一句话概括四项改动，版本更新日志按现有流程汇总三份产品更新说明。#34 属于公开仓库清理。

> Arcfold 可以随对话调整目标，拆出子目标或补上上层目标后，本轮学到的内容和后续对话都能跟过去，回答前的目标判断最多可等 60 秒，公开仓库也清理了旧开发工具。

## 预期效果

用户把话题转向更具体的任务时，助手可以当轮调整目标，让这一轮学到的内容归到调整后的目标下。助手回答前会看到当前目标的完整路径，可以在这条路径的相应层级下拆出子目标。新增上层目标后，本轮转到新目标，下一轮也从那里开始。回答前的目标判断一旦返回，聊天随即继续。开发工具统一在本地仓库维护。

## 考虑过的其他做法

仅用当前已发行的 0.6.0 继续体验，或只发 #49，都会漏掉本次指定的改动。

## 验收标准

- 对照 0.6.0 的源码，确认最终选定的四张 PR 均已合入。核心包、界面包和依赖记录使用同一版本，核对生成的逐项更新说明与发行 PR 摘要。
- 用本次候选的两份包验证安装、对话、更新、失败恢复和重启读回，并保存结果。对照原版 standard 和 Arcfold 主助手，核验实际请求头及模拟服务收到的工具清单。
- 按候选验收结果和实际包申请公开发布授权。

## 风险

目标判断一直没有返回时，用户可能比以前多等 48 秒。主助手能调整目标，它在实际对话中是否判断恰当仍需体验确认。
