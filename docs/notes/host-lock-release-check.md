# 决策：[029-D1] 修复定版时宿主依赖校验的误报

Status: proposed
observed_in_version: 0.6.0 候选
fixed_in: pending
user_verified: pending

## 来源

交付 028 的 PR #44 发行检查失败。GitHub 检查 44323407319 的 tree-host-contracts 用例报告锁文件摘要不符，定版差异只改变 Arcfold 自身的两个版本字段。

## 问题

PR #44 为 0.6.0 定版。GitHub 自动检查中，桌面模拟测试有 1115 项通过，1 项失败。失败的宿主依赖测试在读取包之前，就因锁文件的 SHA-256 摘要与保留样例里的摘要不同而退出。旧锁文件和定版锁文件逐项比较，差异仅为顶层版本和根包版本从 0.5.4 变成 0.6.0，依赖版本、下载地址和完整性信息均一致。

## 方案

保留运行证据中的原始锁文件摘要。测试另外将锁文件解析为 JSON，只排除顶层产品版本和根包产品版本，对其余结构计算摘要并与固定基准比较。用当前主分支的锁文件计算基准，保留原有 Node、平台、宿主包版本、包描述和实际入口文件的检查。改动范围限于宿主测试与固定样例，产品运行代码及依赖锁文件保持原状。

## 预期效果

常规定版可以继续通过宿主依赖检查。任何实际依赖变化仍会触发检查失败。修复合入后，0.6.0 在原发行任务和 PR #44 上按新主分支重新定版。

## 考虑过的其他做法

每次定版重录一次整个锁文件的摘要。这样下次定版仍会踩到同一处，且发行提案只允许变更版本与汇总说明。

## 验收标准

- 用 0.5.4 和 0.6.0 的锁文件分别运行校验，只改变两个产品版本字段时得到同一摘要。
- 修改任一依赖的版本、下载地址或完整性值，校验能够识别变化。
- 现有宿主行为测试通过，依赖包版本和入口文件摘要仍严格匹配固定样例。

## 风险

如果忽略字段过多，真实依赖变化可能逃过检查。实现只排除上述两个字段，保留整份原始锁文件的摘要供查证。
