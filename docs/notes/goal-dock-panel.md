# 决策：[050-D1] 输入框上方的目标改成和原生任务面板同款的常驻面板，重画目标链

Status: proposed
observed_in_version: 0.7.0
fixed_in: pending
user_verified: pending

## 来源

开发者反馈 F45（2026-11-20 登记，附两张截图），日常 DSH 装的是 0.7.0 预览（第 3 次候选）。Murphy 原话：对前端目标展示的反馈 进入一个决策：前端展示方式模仿原生任务组件 放在它下方常驻展示 改icon 也可点开 重新设计目标链展示方式 可以和arcfold页面呼应

## 问题

日常 DSH 对话页，输入框上方现在有两样东西：原生的「任务 3 已完成」面板，和它下面 Arcfold 的目标胶囊（截图里的「● 我 › Murphy 在月底前完成申请，让对方清楚认识 Murph… 进行中」）。

两者看起来不是一套东西。任务面板是和输入框同宽的一整条，左边清单图标，右边展开箭头，点开是一列条目。目标胶囊是一个最宽 360px 的小按钮，整条目标链挤在一行里用 › 连起来，层级一深就被省略号截掉，看不出当前在做哪一层。点它弹出一个全屏遮罩的详情框，和 Arcfold 页面里的目标树也不像。

代码位置：胶囊是 `packages/method-ui/src/tree-view.mjs` 的 `TreeDock` / `NodeChip`，样式在 `tree-style.css` 的 `.tree-dock`、`.tree-chip`。它注册在宿主的 `conversation.input.dock` 插槽，order 20，和排队面板同一档；原生任务面板是 order 0，原生目标条 order 10 已被 Arcfold 隐藏。

## 方案

把 `TreeDock` 改成一个和原生任务面板同款的「目标」面板，常驻在任务面板正下方。

1. 位置：插槽 order 改为 5，排在任务面板（0）之后、排队面板（20）之前。没有任务面板时它自己贴在输入框上方。只要开了目标树模式就一直显示，本聊天还没归到目标时显示「还没有归到目标」。
2. 外观照任务面板做：同宽、同圆角、同底色和描边、同字号，宽度用宿主的 `--dsh-composer-side-clearance` 和 `--dsh-composer-dock-inset` 计算，颜色用 `--dsw-alias-*` 主题变量，深浅色都跟随宿主。宿主的样式类是打包后的哈希名，不能直接复用，在 `tree-style.css` 里照着写一份。
3. 折叠时一行：左边换成目标图标（靶心，14px，自己画的 SVG，和清单图标同尺寸同颜色），然后「目标」两字，再是当前目标的名字和状态，例如「盘点申请所需的结果、已有证据与缺口 · 进行中」，右边展开箭头。默认折叠，和任务面板一致；本页内记住展开状态。
4. 展开后重画目标链，样式照 Arcfold 页面左侧目标树：从「我」开始每层一行，往下逐级缩进 14px，每行是状态圆点、名字、状态字。当前目标那一行用 Arcfold 页面选中行同样的浅色底。一轮归到多个目标时，共同的上级只出现一次，分叉画成小树。
5. 点展开后的某一行，打开那个目标的详情，沿用现在的详情框和其中内容，不改详情本身。
6. 目标范围选择（`AttributionRange`，候选太多要用户选一支时出现的那块）挪进面板展开区。需要用户选择时面板自动展开，折叠行改成提示「需要选择目标范围」。

不改：目标数据、5 秒轮询、详情框内容、Arcfold 页面本身、旧模式（目标树模式关闭时）的显示。

## 预期效果

输入框上方变成上下两条同款面板：任务一条、目标一条。不点开就能看到当前在做哪个目标、什么状态；点开能看到这个目标在整棵树里的位置，和 Arcfold 页面左侧一个样子。

## 考虑过的其他做法

- 只把胶囊放宽、允许换行。放弃原因：还是一行文字串，层级看不清，也不像任务面板。
- 把目标塞进原生任务面板里当一组条目。放弃原因：任务面板是宿主的组件，Arcfold 改不了它的内容；硬插会随宿主升级坏掉。
- 点行直接跳到 Arcfold 页面并选中该目标。暂不做：还没核实插件能不能从输入区切换对话页的标签；先沿用详情框，核实可行后可以另开任务。

## 验收标准

- 模型拿到的工具和原版 DSH 一致：未安装 Arcfold 时用 standard 取原版完整工具基准；安装后 arcfold-main 核对 bash、read、write、edit、glob、grep（Arcfold 会关闭 standard）。实际会话 request/header 与模拟服务收到的清单均须核对，缺项判失败。

- 目标树模式下，目标面板注册在 `conversation.input.dock`，order 5，排在任务面板之后、排队面板之前；原生目标条仍被隐藏。有测试。
- 折叠行显示目标图标、「目标」、当前目标名和状态；没有归属时显示「还没有归到目标」。有测试。
- 展开后按层级逐行显示从「我」到当前目标的链，当前目标行有选中样式；多个目标时共同上级只出现一次。有测试。
- 点展开区某一行打开对应目标的详情。有测试。
- 需要选择目标范围时面板自动展开并显示选择；保存范围的原有行为和测试不变。
- 目标树模式关闭时显示和现在一样。原有 method-ui 测试全部通过。
- 日常观察（不作为发布条件，单独记录）：装上含本改动的版本后，在日常 DSH 截图对比任务面板和目标面板，看是否像同一套、目标链是否看得清。

## 风险

- 外观是照宿主样式手抄的，宿主以后改任务面板的样子，两者会再次不一致，要跟着改。
- 插槽 order 和宽度变量是按本机装的宿主客户端（0.1.0-rc.6）读的，产品依赖的宿主版本是 0.2.2-rc.1，开工时要先在该版本上核对 order 和变量名。
- 这是新功能，不进 0.7.0 当前候选，随 0.7.0 之后的版本发。
