# 决策：[028-D2] 发行 0.6.0，交付普通协作学习和超限恢复

Status: proposed
observed_in_version: 0.5.4
fixed_in: 0.6.0
release_source: 3ddb1e249665e58ebf3c940d22a7fd06072c4b8c
user_verified: pending

## 来源

开发者要求在普通协作学习合入后发版。基础改动为交付 027（PR #43）和同一主线上的交付 025（PR #42）。

## 问题

日常 0.5.4 仍只从明确纠正中学习。交付 027 增加了从普通协作中学习的能力，交付 025 修复了学习输入超过模型能处理的长度后队列卡住的问题。两项改动都已合入主分支，用户安装的版本尚未包含它们。

## 方案

以 PR #45 合入后的主分支为发行基线。相较原基线只增加交付 029 的宿主测试修复和决策记录，产品代码及依赖未变。发布 0.6.0，同步核心包、界面包与依赖锁定文件的版本，并将交付 025 和 027 两份说明汇入版本记录。发行提案只做定版和汇总。

先用同一源码构建两次并逐字节比对安装包。用隔离环境中的模拟服务做完整桌面验收，通过后再按两份安装包的校验值申请公开发行授权。

## 预期效果

用户更新到 0.6.0 后，普通对话里表达的偏好、处境和做法可以进入后续协作。遇到已明确拒绝且没有输出的超限请求时，学习队列可以恢复。

## 考虑过的其他做法

发 0.5.5。此次除了修复队列，还新增普通协作学习并恢复自动修正已学内容，采用 0.6.0 表明用户可见行为有新增。

## 验收标准

- 两份安装包均为 0.6.0，来自同一固定源码，两次构建结果逐字节一致。
- 在隔离账户实际走完安装、合成对话、下载失败恢复、更新和重启读回。对标准会话，在实际会话请求头与模拟服务收包两侧都核对原版完整工具清单。对 Arcfold 主助手，在两侧都核对 bash、read、write、edit、glob、grep。
- 版本说明能对应两份已合入的改动。公开发行附件和 npm 上的两份包都与这次通过验收的原包一致。

## 风险

交付 024 的 0.5.4 实际验收未通过。升级与重启须用本次候选重新验证，任何失败或证据不足都暂停公开。真实模型的学习效果另以用户更新后的观察记录。
