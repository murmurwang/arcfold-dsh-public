# 对话、目标与实际工作怎样连起来

用户在聊天中说明想做什么、纠正方向或要求继续。主助手照常使用 DSH 的工具完成工作；Arcfold 在后台整理目标、子目标、进展与它们同实际工作的联系。用户不必另填创建、委托或关联表单。目标与正在做的事只在 Arcfold 页签查看，必要时补充原话、暂停或继续。

## 一次委托的实际顺序

1. 主助手根据本轮真实用户要求，通过 arcfold_start_work 明确当前阶段、完成条件与需等待的边界。Arcfold 保存依据并调用 DSH 的原生执行服务。阶段结束前，主助手提交继续、等待或完成决定；每个继续决定只许可下一轮，没有决定则停下。旧 create_goal 工具与 /goal 命令从主预设撤下，唯一原生执行驱动保留。历史原生委托仍按真实命令或模型工具回执登记，保留来源，不伪装新用户要求。
2. 工作记录只证明已经委托和实际执行，不机械新建长期目标。若本轮主助手确实成功调用 arcfold_link_goal，保存它所选择的精确目标定义和原生工作定义。旧历史选择不能重新套到后来修改的工作上。
3. 没有既定联系时，仍由原有一次后台 Learn 读取交付、原文和本次工作。它在目标的 workLinks 中明确选择工作编号、理由和来源。代码检查编号、会话、来源和定义，一份学习分区中同一工作只能联系一个明确目标。没有选择就没有关系；不按标题、最近目标或目标列表位置猜测。
4. 获得 Arcfold 阶段许可的后续轮次，会读取此前已建立且仍有效的目标完整定义、进展、关系、相关理解及原件，同时读取当前阶段及用户原话。普通新对话仍由主助手判断相关性，不因为某目标最近活跃就强行注入它的全文。
5. 交付保存真实结束原因，Learn 更新知识与进展。完成一次工作不代表长期目标已经实现；目标联系也不扩大原始委托、工具或费用权限。

未完成学习时，页签可显示“当前工作，目标联系尚在整理”，主执行不会等待它。目标定义或工作定义改变后，旧联系明确待复核，旧正文退役；下一次 Learn 获得待复核身份，主助手仍可按当前目标目录和原文重新判断。此过程没有额外评审调用、重试循环或第二个调度器。

## 冻结材料与晚到进展

同一轮已经取得的完整背景保持原样。后台仅更新进展时，程序通过已有目标变更审计核对真正的旧版本、未变的定义及仍有效的原件，允许该冻结材料完成本轮；新进展留给下一轮，不热补。

定义、来源、目标关系、追踪控制或工作联系的目标改变不属于纯进展更新，旧背景不能继续采用。同一工作与同一目标定义的重复联系，只要原生定义和新旧来源仍有效，就保留本轮旧正文，不因新联系编号而打断，也不热替换新理由。尚未取得完整正文的首次 arcfold_link_goal 选择仍要求目录中显示的精确版本；旧选择得到明确工具拒绝，不偷偷改成新材料，不由程序重试。这个拒绝不删除已有工作联系，也不阻止普通答复。

## 自然纠正与追踪

主助手理解新的真实用户原话。原有 Learn 的 controlProposal 可将目标背景追踪解释为继续、暂停或结束，记录为助手的可纠正判断，不制造一条用户亲自点击的决定。没有当前 owner 原话、只有自动续轮或历史材料时，不能改变追踪。

旧明确人工决定完整保留。只有能核实原话最初进入原生待处理队列的时间晚于人工控制，新的解释才可取代追踪状态；旧决定缺少这样的原始时序证据时，不猜测覆盖。晚回学习仍须通过原目标版本检查。背景学习不签发执行许可；明确暂停或结束目标时，Arcfold 也停止与之绑定的阶段。下一次发送和工具执行再次检查目标与阶段依据。

“围绕这个目标讨论”仍把用户填写的本次原话经原生 prompt 发送，精确绑定请求编号、正文和当前主助手；不是替用户生成新指令。结果未知不重发。来源失效时保留身份和原因，不继续使用旧正文。

## 暂停、修改与继续实际工作

Arcfold 页签上的工作按钮操作同一个原生执行对象。停止调用原生 pause；它取消当前轮并禁止自动继续，但不声称已经运行的后台进程被强杀。普通聊天仍可继续。

用户在聊天中修改工作方向时，主助手通过 arcfold_revise_work 保存新的具体阶段，旧许可失效，执行保持停止；用户同时委托继续时，再单独调用 arcfold_resume_work。程序核对真实调用、准确执行版本及新收到的原话。中途插入的新要求优先处理，旧继续决定失效。后台学习和自动通知没有新增恢复资格。页签也保留明确继续按钮。

网页决定先记录请求身份，再调用原生服务并核对实际持久回执与阶段保存结果；确认前执行等待。相同请求只读回结果，未知不重发。重启读回历史但保持未激活；旧版没有阶段的委托需根据新的用户要求先明确当前阶段。旧来源被撤回后，新阶段可用新的完整委托重新建立权限，旧原件仍留作历史。

## 来源与验证范围

src/goal-execution.mjs 保存当前阶段、依据与单轮许可；src/goal-execution-tool.mjs 接入主助手与原生执行检查。src/goal-work.mjs 保存历史工作引用、模型联系及只读投影；src/native-continuation.mjs 区分历史委托事实与当前阶段来源；src/session-bridge.mjs 在已有持久截止内接线；src/learning-goals.mjs 只提交目标理解与联系。具体行为与检查位置见 [goal-control.md](goal-control.md)。

原生输入栏的目标横条通过官方同标识插槽覆盖隐藏，原 ui-goal 插件和命令历史渲染保留。当前阶段及等待原因集中在 Arcfold 页签显示。没有增加执行驱动或监督模型；内容判断仍由同一个主助手作出。源码与固定输出检查证明工程行为，实际模型判断和运行结果由独立验证记录说明。
