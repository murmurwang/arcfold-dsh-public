# 普通账户的 DSH 原版安装与更新复测

制作测试包时输入两次发行的目录，以及构建用的 npm 缓存。脚本按现有归档校验值镜像核心包、界面包和锁定的公开依赖。预备版演练可读取构建清单，正式发行验收使用 `release.json` 所指的原包。

    python3 -B prepare.py --older OLD_DIR --newer NEW_DIR --npm-cache CACHE_DIR --output NEW_SHARED_DIR

1. 用 macOS 快速用户切换登录普通账户 `arcfold-test`。在 Finder 打开新制备的测试目录，双击 `Run-DSH.command`。
2. 在打开的 DSH 里选择「插件」→「添加插件」，输入 `@arcfold/dsh`，启用并完成首次设置。按 ⌘Q 退出 DSH。
3. 再双击同一入口。按终端给出的测试文字发一条消息。看到合成回复和目标后，在插件详情选中新版并确认。第一次下载会返回模拟错误，等旧版恢复。出现错误后运行 `Run-DSH.command restored`，它会核对旧包、对话和失败请求，然后恢复下载。
4. 回到同一插件页，重新选择新版并确认。更新完成后按 ⌘Q，再双击同一入口。打开之前的会话和目标，运行 `Run-DSH.command finish`。它会读回两份实际安装包、界面中的原话与回复，以及同一个目标和保存记录。终端给出 `result.json` 的位置。
5. GitHub 地址安装用单独的测试窗口。运行 `Run-DSH.command git`，在「添加插件」输入已批准的 GitHub 安装地址。打开目标插件详情后运行 `Run-DSH.command git-section`。脚本检查保存的安装来源，再读取详情页是否显示版本区块。地址不可安装时保留界面错误和来源，记录为未验证版本区块。

发行门禁核对本机注册表的安装、对话、失败恢复、更新和重启读回。GitHub 来源的观察独立记录。

带参数的动作在终端执行，路径含空格时拖入文件得到完整命令。测试窗口只使用该账户中新建的资料目录、固定的签名 DSH 0.2.2-rc.1 和本机模拟模型。
