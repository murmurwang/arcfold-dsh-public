# npm 发布隐私核对

安装包内容通过检查，不代表公开发布信息也通过检查。发布工具可能在上传时追加本机路径；注册表还会记录发布账号。

## 发布前

1. 仍从已合入源码取得经过构建、许可和隔离验收的原包。核对版本与内容摘要，不因清理发布信息而重新打包或替换已验收的文件。
2. 核对将上传的发布信息，特别是 `_from`、`_resolved` 等来源字段。不要把个人目录中的绝对路径交给正式发布命令后，仅凭安装包扫描结果放行。
3. 若使用命令行发布原包，先把同一份归档复制到不含个人标识的临时目录，再核对复制前后的摘要。该方式仍可能公开临时路径；需要完全省略本机路径时，应从已验收归档读取包信息，删除客户端追加的本机来源字段，并在正式上传前检查实际请求内容。任何新发布入口都须经过既有审阅和授权流程。
4. 发布账号的邮箱可能由 npm 服务端写入公开信息。只能使用账号所有者接受公开的邮箱。当前账号所有者已明确接受现有邮箱，本次清理不更改邮箱或登录设置。

## 发布后

从公开 npm 注册表重新读取完整包信息，检查每个发行版本的来源字段、发布账号和维护者资料。再次核对版本、依赖、默认安装版本以及下载包的完整性摘要；不要只查看 npm 网页或包内的 `package.json`。

## 已有公开记录

新版本或本地修改不会自动清理旧版本记录。先确认平台支持的处理方式并保留处理前后的核对证据；没有实际读回结果时，不得称为已经删除。涉及平台支持请求时，先准备明确的删改范围，并由账号所有者授权联系。

下架版本会使该版本无法继续安装，且不能再用相同包名和版本号重新发布，不作为默认隐私清理办法。GitHub 的旧提交、提案和标签同样保留历史，需要单独评估；普通提交只改变新的源码版本。

## 已做的离线核对与边界

使用 npm 11.21.2 自带的包读取与发布组件，对本机临时服务发送合成包：个人目录中的归档会产生来源路径，复制到中性目录后不再含个人目录，删除来源字段后请求中不再含这两个字段。三种请求携带的归档字节相同。核对未携带真实凭据、未连接 npm、未发布包；它不证明线上服务允许修改历史记录，也不证明服务端不会添加其他信息。
