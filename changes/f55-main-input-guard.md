# 主对话继续前刷新目标背景并说明核对失败原因

## 动机

断线后继续时，目标背景可能在步骤准备和实际发送之间更新。原来的发送前检查把背景过期和用户原话、目标归属异常都合成同一句英文报错，事后也无法区分。

## 改动

- 在原生请求定稿前重新核对本轮原话、目标范围和已准备的背景。只有背景版本变化时重新挂载背景；用户原话、回合、归属或背景消息不符时仍然拒绝发送。
- 刷新沿用原生会话记录，不重放用户输入和已执行的工具。后续计数、请求校验和模型可见内容记录使用刷新后的背景。
- 保留 `MAIN_INPUT_GUARD` 错误码，提示改为中文。诊断保存失败项目、会话和回合标识及新旧背景摘要标识，不保存消息正文。

## 测试

- 通过：新增 6 项原生循环与本机模拟服务检查，覆盖连接中断后继续时刷新背景、四类不可刷新异常及定稿后的再次变化；诊断正文排除检查通过。请求头与服务收到的工具清单一致，包含 bash、read、write、edit、glob、grep。
- 通过：上下文与原生模型接入回归 19 项；任务所有权与原生模型记录回归 28 项。
- 修复前，相同连接中断后继续的合成用例复现了原来的英文核对失败。
- 未验证：原始故障现场的具体触发原因、真实窗口体验，以及干净 standard 与安装后完整工具基准的窗口验收。这些结论不能由模拟检查代替。
