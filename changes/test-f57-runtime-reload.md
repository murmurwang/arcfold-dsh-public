# 启动时不再为每条历史学习重复计算同一份统计

## 动机

旧的任务读取优化后，启动仍会为每条已完成学习重新整理相同的历史信号，并逐轮查询事件顺序。此前的速度测试跳过了真实的完成后检查，未覆盖这个瓶颈。

## 改动

启动恢复和每次后台扫描在同一段同步执行期间共用未变化的历史统计及事件顺序映射。记录写入、回滚、其他连接写入或宿主刷新原文都会让复用结果失效；执行结束立即丢弃。每条恢复、检验触发和来源核对仍按原流程执行，没有删除记录或减少检验。

## 测试

新增真实恢复链路与原实现的任务、归属、分类结果对照；用420条任务、85条已完成学习和7000条历史事件检查恢复耗时，并检查目标和轮次详情。覆盖更正、重新归属、原文撤回、数据库并发写入、回滚、返回值隔离及跨异步边界拒绝。所有材料均为合成数据，不调用付费模型。真实安装后的速度与模型连接仍须分别验证。

## AI 参与

开发者确定修复范围与验收目标；Codex完成诊断、实现及测试，审阅与合入遵循项目当前有效的授权流程。
